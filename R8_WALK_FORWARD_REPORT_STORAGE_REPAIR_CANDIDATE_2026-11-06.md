## Source classification

The report-builder null conditions are not compatible with the Gate 5F state:
- `createdAt` is generated by `new Date().toISOString()`;
- the calibration dataset carries the same frozen configuration hash supplied to the report builder;
- the default expanding-fold builder returns either zero folds or exactly three folds, and Gate 5F had already passed the zero-fold LOW_SAMPLE branch.

Therefore the remaining combined condition is report persistence.

The logical report embeds each calibration artifact in full. Each artifact governance payload repeats the dataset-wide `inputLineageHashes` array. For a roughly 59k-candle 60-day M1 evidence window, that large lineage array is repeated across up to 12 fold/window artifacts, creating a tens-of-megabytes report JSONB write even though the statistical result itself is small.

## Repair design

- preserve the logical `EquatorWalkForwardReport` and its existing `reportHash` unchanged;
- persist each immutable `EQUATOR_CALIBRATION_ARTIFACT` individually, preserving its full lineage and identity;
- persist `EQUATOR_WALK_FORWARD_REPORT` as a compact artifact-reference descriptor;
- reconstruct the exact logical report on read by loading referenced immutable artifacts;
- recompute and verify the original logical report hash before returning the report;
- retain backward compatibility with older full-report records;
- add explicit persistence failure codes for artifact read/write/collision vs report descriptor read/write/collision;
- emit logical report byte size, lineage count, aggregate approval and per-fold governance metrics before persistence.

No calibration parameter, approval threshold, model output, dataset hash, report hash, or trade authority is changed.
